This document defines the shared data structures used between project modules.

All modules must follow these structures.

---

## 1. DetectionEvent

A `DetectionEvent` represents one vehicle observation generated by the ANPR module.

### Example

```json
{
  "event_id": "evt_001",
  "plate_number": "KA01AB1234",
  "confidence": 0.96,
  "camera_id": "CAM_07",
  "timestamp": "2026-08-25T18:21:32Z",
  "latitude": 12.9716,
  "longitude": 77.5946,
  "direction": "NORTH",
  "vehicle_type": "car",
  "snapshot_path": "data/snapshots/evt_001.jpg"
}
````

---

## 2. DetectionEvent Fields

| Field           | Type            | Required | Description                            |
| --------------- | --------------- | -------- | -------------------------------------- |
| `event_id`      | string          | Yes      | Unique identifier for the detection    |
| `plate_number`  | string          | Yes      | Recognized license plate number        |
| `confidence`    | float           | Yes      | Recognition confidence from 0.0 to 1.0 |
| `camera_id`     | string          | Yes      | Camera that produced the detection     |
| `timestamp`     | ISO 8601 string | Yes      | Time of detection in UTC               |
| `latitude`      | float           | Yes      | Camera latitude                        |
| `longitude`     | float           | Yes      | Camera longitude                       |
| `direction`     | string          | Yes      | Vehicle movement direction             |
| `vehicle_type`  | string          | Yes      | Vehicle category                       |
| `snapshot_path` | string or null  | No       | Path or URL of the detection snapshot  |

---

## 3. Confidence

`confidence` must be between:

```text
0.0 and 1.0
```

Example:

```text
0.96 = 96%
```

Confidence must represent the actual model/pipeline output.

The system must not claim an accuracy percentage that has not been measured on a validation dataset.

---

## 4. Timestamp

All timestamps must use ISO 8601 format in UTC.

Example:

```text
2026-08-25T18:21:32Z
```

Do not use different timestamp formats in different modules.

---

## 5. Camera

A camera is represented as:

```json
{
  "camera_id": "CAM_07",
  "name": "MG Road Junction",
  "latitude": 12.9716,
  "longitude": 77.5946,
  "road": "MG Road",
  "direction": "NORTH"
}
```

### Camera Fields

| Field       | Type   | Required | Description                |
| ----------- | ------ | -------- | -------------------------- |
| `camera_id` | string | Yes      | Unique camera identifier   |
| `name`      | string | Yes      | Human-readable camera name |
| `latitude`  | float  | Yes      | Camera latitude            |
| `longitude` | float  | Yes      | Camera longitude           |
| `road`      | string | Yes      | Associated road            |
| `direction` | string | Yes      | Main monitored direction   |

---

## 8. Detection Event Lifecycle

A detection moves through the system as follows:

```text
Camera / Video
      ↓
ANPR Module
      ↓
DetectionEvent
      ↓
Backend
      ↓
Database
      ↓
 ┌──────────────┬────────────────┬──────────────┐
 ↓              ↓                ↓
Trajectory    Analytics        Alerts
 ↓              ↓                ↓
 └──────────────┴────────────────┘
                ↓
               API
                ↓
            Frontend
```

---

## 9. Module Inputs and Outputs

### ANPR Module

**Input:**

* Video
* Image frames
* Camera metadata (camera_id, location, direction)

**Output:**

```text
DetectionEvent
```

The ANPR module is responsible for:

* vehicle detection
* license plate detection
* image preprocessing
* OCR
* confidence estimation
* creation of standardized `DetectionEvent` objects

---

### Backend Module

**Input:**

```text
DetectionEvent
Camera
```

**Output:**

* stored detection records
* trajectory data
* analytics results
* alerts
* API responses

The backend owns persistence, APIs and integration between modules.

---

### Trajectory Module

**Input:**

```text
DetectionEvent[]
```

**Output:**

```text
VehicleTrajectory
```

The trajectory module orders detections chronologically and reconstructs the observed movement of a vehicle across cameras.

---

## 10. VehicleTrajectory

A vehicle trajectory represents the chronological sequence of observed camera detections associated with a recognized plate number.

### Example

```json
{
  "plate_number": "KA01AB1234",
  "first_seen": "2026-08-25T08:42:00Z",
  "last_seen": "2026-08-25T18:27:00Z",
  "detections": [
    {
      "camera_id": "CAM_01",
      "timestamp": "2026-08-25T08:42:00Z",
      "latitude": 12.9716,
      "longitude": 77.5946,
      "direction": "EAST"
    },
    {
      "camera_id": "CAM_04",
      "timestamp": "2026-08-25T08:50:00Z",
      "latitude": 12.9780,
      "longitude": 77.6010,
      "direction": "NORTH"
    }
  ]
}
```

---

## 11. VehicleTrajectory Fields

| Field          | Type            | Required | Description                               |
| -------------- | --------------- | -------- | ----------------------------------------- |
| `plate_number` | string          | Yes      | Vehicle license plate                     |
| `first_seen`   | ISO 8601 string | Yes      | Earliest observed detection               |
| `last_seen`    | ISO 8601 string | Yes      | Latest observed detection                 |
| `detections`   | array           | Yes      | Chronologically ordered camera detections |

Each trajectory detection contains:

| Field       | Type            | Required |
| ----------- | --------------- | -------- |
| `camera_id` | string          | Yes      |
| `timestamp` | ISO 8601 string | Yes      |
| `latitude`  | float           | Yes      |
| `longitude` | float           | Yes      |
| `direction` | string          | Yes      |

---

## 12. Traffic Analytics Data

Analytics may consume detection and trajectory data.

The analytics module may produce:

### Traffic Density

```json
{
  "camera_id": "CAM_07",
  "road": "MG Road",
  "vehicles_per_hour": 1240
}
```

### Congestion

```json
{
  "from_camera": "CAM_12",
  "to_camera": "CAM_16",
  "travel_time_minutes": 18,
  "normal_travel_time_minutes": 9,
  "congestion_level": "HIGH"
}
```

### Origin-Destination

```json
{
  "origin_zone": "ZONE_A",
  "destination_zone": "ZONE_D",
  "vehicle_count": 1540
}
```

These structures may be extended when implementing the analytics module, but changes to shared interfaces must be communicated to the lead.

---

## 13. Alert

An alert represents a rule-based or analytical event that requires attention.

### Example

```json
{
  "alert_id": "alert_001",
  "plate_number": "KA01AB1234",
  "type": "BLACKLISTED_VEHICLE",
  "camera_id": "CAM_17",
  "timestamp": "2026-08-25T18:44:00Z",
  "severity": "HIGH",
  "message": "Blacklisted vehicle detected"
}
```

### Alert Fields

| Field          | Type            | Required | Description                       |
| -------------- | --------------- | -------- | --------------------------------- |
| `alert_id`     | string          | Yes      | Unique alert identifier           |
| `plate_number` | string          | Yes      | Vehicle associated with the alert |
| `type`         | string          | Yes      | Alert category                    |
| `camera_id`    | string          | Yes      | Camera where alert was generated  |
| `timestamp`    | ISO 8601 string | Yes      | Alert time in UTC                 |
| `severity`     | string          | Yes      | Alert severity                    |
| `message`      | string          | Yes      | Human-readable explanation        |

---

```text
DetectionEvent[]
```

```text

```

```text
DetectionEvent[]
VehicleTrajectory[]
```

```text
Traffic Density
Congestion
Origin-Destination results
```

### Alerts

Consumes:

```text
DetectionEvent[]
VehicleTrajectory[]
```

Produces:

```text
Alert
```

### Frontend

Consumes:

```text
Backend API responses
```

The frontend must not directly depend on the internal implementation of ANPR, analytics or database modules.

---

## 16. Shared Contract Rules

1. Do not create alternative versions of `DetectionEvent`.
2. Do not rename shared fields without approval from the lead.
3. Do not change shared field types without approval from the lead.
4. New shared fields must be discussed with the lead before implementation.
5. Module-specific internal objects are allowed.
6. Shared data exchanged between modules must remain compatible with this document.
7. Database models and API schemas must remain consistent with the documented shared structures.
8. Any approved contract change must be reflected in this file before dependent code is merged.
9. Latitude and longitude must use decimal degrees in WGS84 coordinates.
